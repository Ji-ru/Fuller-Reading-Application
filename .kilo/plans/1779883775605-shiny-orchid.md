# Plan: Implement Upload Recording in Student_Reading_Activity.tsx

## Objective
To upload audio recordings to Google Drive after a reading activity attempt by using the `uploadRecording` function from `DriveUploadController.ts` in `Student_Reading_Activity.tsx`.

## Changes Required

### 1. Update DriveUploadController.ts
Add support for alphabet recordings by defining a new metadata type and updating the union.

#### Changes:
- Add `AlphabetUploadMetadata` type.
- Update `UploadMetadata` union to include the new type.

```typescript
// Existing types
type WordUploadMetadata = {
    kind: 'word';
    chapterId: number;
    lessonId: number;
    targetWord: string;
    miscueCount: number;
    accuracyRate: number;
};

type PassageUploadMetadata = {
    kind: 'passage';
    passageTitle: string;
    miscueCount: number;
    accuracyRate: number;
};

// New type for alphabet
type AlphabetUploadMetadata = {
    kind: 'alphabet';
    letter: string;
    miscueCount: number;
    accuracyRate: number;
};

export type UploadMetadata = WordUploadMetadata | PassageUploadMetadata | AlphabetUploadMetadata;
```

### 2. Update Student_Reading_Activity.tsx
Import the uploadRecording function and call it after obtaining the transcription and analysis results.

#### Changes:
- Add import: `import { uploadRecording } from '../../Controller/DriveUploadController';`
- Modify the `handleRecordToggle` function to upload the recording after analysis.

#### Detailed Steps in handleRecordToggle:
1. Stop recording to get the audio file path.
2. Transcribe the audio file using `transcribeAudioAPI`.
3. Analyze the transcription by calling `analyzeReading` (this updates state with miscues, accuracyString, etc.).
4. After analysis, extract metadata based on the activity type:
   - For **word**:
     - kind: 'word'
     - chapterId: `readingMaterial.aralin` (assumed to be present in Word type)
     - lessonId: 0
     - targetWord: `getTargetText()`
     - miscueCount: `miscues.length`
     - accuracyRate: `convertAccuracyStringToNumber(accuracyString)`
   - For **passage**:
     - kind: 'passage'
     - passageTitle: `readingMaterial.title`
     - miscueCount: `miscues.length`
     - accuracyRate: `convertAccuracyStringToNumber(accuracyString)`
   - For **alphabet**:
     - kind: 'alphabet'
     - letter: `readingMaterial.letter`
     - miscueCount: `miscues.length`
     - accuracyRate: `convertAccuracyStringToNumber(accuracyString)`
5. Call `uploadRecording` with the audio file path and the metadata.
6. Handle any upload errors (log them, but do not block the UI flow).
7. Proceed to set `isReadingCompleted` to true.

#### Error Handling:
- Wrap the upload call in a try-catch block.
- Log any errors to the console but do not alter the existing flow (e.g., do not show alerts to avoid disrupting the user experience).

## Assumptions and Notes
- The `readingMaterial` for word type is assumed to have an `aralin` property (number) as per the user's response. If this property is absent, a fallback (e.g., deriving chapterId from the letter's char code) may be needed.
- The `convertAccuracyStringToNumber` function is already defined in the component and used elsewhere.
- The upload is attempted only after successful transcription and analysis to ensure we have the required metadata (miscue count and accuracy rate).
- The upload is non-blocking; errors are logged but do not affect the activity completion state.
- Only the `handleRecordToggle` path is modified because it uses the direct transcription API (`transcribeAudioAPI`). The hook-based transcription path (`useSpeechToText`) is not currently used in this component, so no changes are needed there.
- If the hook-based transcription path is used in the future, similar logic should be added there.
