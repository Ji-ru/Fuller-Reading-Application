# Implementation Plan: Fuller Reading Application Fixes

## Overview
This plan addresses 6 distinct issues requiring fixes across the application: text display overflow, admin dashboard crash, user editing limitations, class joining workflow, registration functionality, and miscue reporting.

---

## 1. Student Screen - Text Display Auto-Adjust Fix

### Problem
Letter (titik), Words (salita), and Passage (talata) display modules have fixed height containers that cut off text when content is long or wraps to multiple lines.

### Files to Modify
- `src/Components/Student/Reading/TextDisplay.tsx`
- `src/UI_Designs/ReadingActivityStyles.ts`

### Solution
1. Remove fixed height constraints from `passageContainer`, `wordCard`, and `letterContainer` styles
2. Use `minHeight` instead of `height` to allow content-based expansion
3. Set `flex: 1` or `flexGrow` on containers to expand with content
4. Add `overflow: 'visible'` where needed
5. Modify ScrollView to properly handle dynamic content height

### Implementation Steps
```tsx
// In ReadingActivityStyles.ts - Change fixed heights to min/max
passageContainer: {
  height: undefined,  // Remove fixed height
  minHeight: 200,     // Minimum only
  flex: 1,           // Allow expansion
}

wordCard: {
  height: undefined,
  minHeight: 180,
  flex: 1,
}
```

## 3. Admin User Edit - Full Information Fields

### Problem
Admin can only edit first name, last name, and email. Need to support all student/faculty information fields as displayed in their respective profile screens.

### Files to Modify
- `src/Screens/Admin/UserManagement.tsx`
- `src/Controller/AuthenticationController.ts`

### Solution
Based on Student Profile (Student_Home/Profile) and Faculty Profile screens, admin needs to edit:

**Student Editable Fields:**
- firstName, middleName, lastName, email
- sex
- dateOfBirth (from studentData)
- gradeLevel (from studentData)
- classCode (from studentData)
- reading_Level (from studentData)

**Faculty Editable Fields:**
- firstName, middleName, lastName, email
- sex
- assignedGradeLevels (from facultyData)
- assignedClassIds (from facultyData)

### Implementation Steps
1. Add comprehensive state for all student fields:
   ```ts
   const [editGradeLevel, setEditGradeLevel] = useState(1);
   const [editDateOfBirth, setEditDateOfBirth] = useState('');
   const [editClassCode, setEditClassCode] = useState('');
   const [editReadingLevel, setEditReadingLevel] = useState<'beginner' | 'intermediate' | 'advanced'>('beginner');
   ```

2. Add state for faculty fields:
   ```ts
   const [editAssignedGradeLevels, setEditAssignedGradeLevels] = useState<number[]>([]);
   const [editAssignedClassIds, setEditAssignedClassIds] = useState<string[]>([]);
   ```

3. Add conditional rendering in edit modal:
   - Show student-specific fields when `selectedUser.role === 'student'`
   - Show faculty-specific fields when `selectedUser.role === 'faculty'`

4. Create dropdown selectors:
   - Grade Level: 1-6 (for student)
   - Reading Level: beginner/intermediate/advanced (for student)
   - Assigned Grade Levels: multi-select (for faculty)

5. Update `handleSaveEdit` to include all fields in `updateUserProfile` call

6. The backend `updateUserProfile` function already supports these nested fields via dot notation

## Design Consistency Requirements
All UI modifications must follow the existing design system to maintain consistency:

### Color System (from Utilities/Theme.ts)
- **Student Colors (C)**: bg, ink, slate, green, teal, sky, mint, coral, purple, orange, yellow, red
- **Faculty Colors (F)**: bg, ink, slate, primary, primaryDeep, primaryLight, coral, white
- **Shared colors**: Radii (sm, md, lg, xl), Shadows (subtle, card, cardLift, button)

### UI Components Pattern
- Cards: White background with borderRadius (16-32), subtle shadow, bordered
- Buttons: Primary (green/coral) with rounded corners (14-20 radius)
- Inputs: Rounded (12-14), bordered with slate/gray borders
- Icons: Consistent sizing (18-24px) with theme-appropriate colors

### Typography
- Font family: Andika-Bold for headings, Andika-Regular for body
- Text colors: C.ink / F.ink for primary, C.slate / F.slate for secondary
